## 5. 复跑与比较协议

1. 先检查manifest中的原引擎、Extract.lean、Lean/Mathlib、库源及题目哈希。不一致则登记新版本，不替换baseline v1。
2. 使用固定七题完整结构，保持ID、变量顺序、假设顺序和目标顺序。不能读取历史证明、DAG或分类标签作为规划输入。
3. 当前独立CLI支持逐题输入；以新目录输出每道题的problem.json，调用`python -B -m phase2 <problem.json> --budget 12`。引擎本身会创建新的UUID运行目录。批量重跑可沿用现有benchmark命令，但必须核对它生成的cases与frozen-seven.json逐值相同，任何差异令该批次不可直接比较。
4. 保存所有成功/失败源码、日志、环境、事件与SHA256；不更新本基线目录或原批次。输出独立comparison.json，使用baseline ID关联。
5. 对时间采用相同预热方式，单线程、相同机器、相同Lean缓存条件；分报搜索、检索、模型、编译、排队及总墙钟。保留个体数据，不只报告平均。
6. 重跑预期验证证明结果与证据一致；不承诺耗时或执行顺序字节一致。新版本不同DAG可视为算法变化，应逐题展示差异。

本轮未新增或改动基准执行器。下一轮若实施三模式runner，它应独立读取上述冻结输入并写新目录；完整接口及资源对照见[AI接入与对照实验设计](AI_INTEGRATION_DESIGN.md)。

## 6. 基准性质

这7道题已经公开且用于开发，是固定回归/对照集，不是对未来AI的严格盲测。类别只是开发者的测试意图，不保证某题数学上必须新建中间引理。真正泛化评估需要另行保留未见题目，但不得替换这7题的长期基线。

本轮没有重新调用Lean编译器；引用的编译证据来自原批次和上轮独立重编译。本轮新增验证针对文件哈希、记录关联、计数和冻结输入一致性。
